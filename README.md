# 蒋莫闻 · 案件后台与完整脚本接收器

内置 **林小女案**、**教授夫妇案**。副 API 读取案底并裁定当前行动；主 API 只收到公开案卷、本轮许可和创作边界。保留角色原有设定、所有开场原文、开场主页与恋爱状态栏。

## 导入与配置

1. 导入交付的完整角色卡 JSON，启用酒馆助手以及卡内唯一脚本 **蒋莫闻 · 完整脚本接收器**。
2. 在页面右下角 **蒋莫闻 · 案卷 → 设置** 填写副 API 地址、模型和 API Key，测试连接。支持 OpenAI 兼容 `chat/completions`。地址可填到 `/v1` 或完整接口；服务须允许浏览器 CORS。
3. 主 API 继续使用酒馆自己的连接设置。此版正式适配 SillyTavern 的 **Chat Completion** 请求；需要支持 `CHAT_COMPLETION_SETTINGS_READY` 事件。
4. 选择案件开场，或在 **案件库** 进入案件。也兼容明确命令“加载林小女案”“加载教授夫妇案”。无需再导入旧案件世界书。
5. 用新聊天开始；解除旧案件世界书的绑定。旧聊天正文及记忆插件已经记住的真相无法由新脚本抹除。

角色卡已包含接收器，**不要再导入一份重复脚本**。单独接收器供作者更新或维护使用：[下载接收器 JSON](https://jhyshl.github.io/jiang-mowen-cases/dist/receiver.tavern.json)。完整个人角色卡在交付目录 `output/`，不公开提交其中原有的个人脚本存档。

## A 方案与插件兼容

副 API 使用独立的 `fetch`、`AbortController`、配置和响应解析，直连用户填写的服务；不调用酒馆的 `generateRaw`、连接管理器、共享生成端点或第三方记忆插件的模型方法，也不改酒馆全局模型设置。密钥只发送到所填接口，默认仅存当前页面；勾选后保存在当前浏览器 IndexedDB。

主请求到达 `CHAT_COMPLETION_SETTINGS_READY` 时，脚本根据请求自己的 `type` 和角色卡标识决定是否处理，等待副 API 后将经过字段校验的公开边界加入该次请求。`quiet`、`impersonate` 以及不含本卡标识的请求跳过。文本补全的同类事件为尽力支持，正式验收范围是 Chat Completion。

不依据全局“最后一次生成类型”判断，也不因无类型的 `GENERATION_ENDED` 事件清除待提交案卷。记忆插件在玩家发送前后、正文完成前后调用模型，都不需要与本脚本争用副模型通道。第三方插件若自行冒用普通正文请求类型、修改所有请求或覆写本文本，仍需单独排查；没有声称覆盖全部插件组合。

## 信息分层与状态

| 内容 | 保存位置 | 主 API 可见 |
|---|---|---|
| 两案完整背景、人物、真相、未发现节点与门槛 | 完整运行脚本内的案件数据 | 否 |
| 私有进度、送检计时、分支快照、重试许可 | 当前浏览器 IndexedDB | 否 |
| 已发现/送检中/结果、已取得证词 | `stat_data.publicCase` 和每轮请求的公开案卷 | 是 |
| 日期、时间、地点、天气、衣着、想法、待办、账本 | 精简 `stat_data`，从原状态栏读取 | 是 |
| 本轮事件许可与创作边界 | 当前请求中临时注入 | 是；不写聊天正文 |

这里隔离的是 **模型上下文**；案件脚本分发给玩家后，懂开发工具的玩家可以读取其中案底。这不是防玩家逆向的加密系统。

原独立 MVU 引擎、Zod 注册脚本、线索判官及旧变量框架条目已移除，统一由接收器里的轻量状态模块管理。不再让主 API 输出 JSONPatch 操作案卷。原 `status_panel` 展示、待办和账本仍然保留；脚本只解析其公开字段。正文的猜测、虚构物证及 `<UpdateVariable>` 不会写入权威线索。

主 API 的“只在边界内创作”仍是提示约束，不能保证任意模型永不越界。本版按需求不增加正文后的第二次 AI 复核；后台只认可经过节点与阶段校验的许可。

## 调查节奏与分支

- 物证区分发现、送检、结果。尸检需登记并等待至少 180 分钟；原案刀具、DNA 等检测保留轮次延迟。台词里随手改时间不能改后台计时。
- 办案轮按 15 分钟推进后台计时；明确“等待三小时”等等待行动按声明时间处理。恋爱聊天不增加办案轮次或检验进度，不按十轮随机发放线索。
- 证词注明来源，不把当事人的不在场说法当作独立证实；供述具有前置物证与多轮询问门槛。复盘须由玩家主动提出，并满足证据链。
- 同一节点每轮最多推进一个阶段，新发现的物证不能在同一轮立刻得到鉴定结论。
- 副 API 只提议节点 ID、动作和玩家原文依据。主 API 接收到的案情文字由脚本从获准阶段取出，不转发副 API 自由文本或推理。
- 正文完成后入档；停止或副 API 失败不入档。相同分支重试复用许可，重新生成、切换回复、编辑和删除后按消息前缀恢复对应快照。
- 副 API 失败时冻结新案情，主 API 可继续日常互动。主 API 自身失败后可重试原回复，许可保持不重复推进；停止生成会放弃未提交许可。
- 存档按聊天与案件分开。案件库可导出/导入进度，不含密钥和案底；跨设备需要复制聊天记录及进度文件，分支匹配依赖相同聊天内容。

## 接收器与后续案件发布

接收器含首版完整脚本的 gzip 离线副本；优先尝试上次成功版本，校验不通过时回退。在线版本清单：[manifest.json](https://jhyshl.github.io/jiang-mowen-cases/dist/manifest.json)。

更新使用内容哈希命名的完整单文件脚本和 SHA-256 校验。首次启动、恢复联网/窗口聚焦及约十分钟轮询时检查，下载完整脚本，生成期间延后替换。上次成功版本和前一版本缓存在本地。更新 URL 限定于本仓库的 Pages、GitHub Raw 与 jsDelivr。

追加案件：在 `src/cases/index.mjs` 的 `cases` 中添加一份独立定义（稳定 ID、公开接警信息、私有案底、节点、前置条件与延迟），并添加可达性和隔离测试。更新 `package.json` 的版本，运行构建和测试，提交新的 `dist/` 与源码到 `main`，Pages 发布后旧角色卡的接收器会自动取得新案件。不要覆盖已有哈希文件，不需要玩家重新导入旧角色卡。更改已有案件的节点 ID/状态结构时，需要保留兼容或明确存档迁移，不能静默丢弃旧进度。

## 开发

Node.js 22 或更新版本：

```powershell
npm install
npm run build
npm test
npm run preview
```

个人卡导出时设置源文件路径（原文件不改写，也不上传）：

```powershell
$env:JMW_CARD_SOURCE='D:/path/to/蒋莫闻 (2).json'
npm run build
npm test
```

输出为 `output/蒋莫闻-案件后台重构-v1.0.0.json`。此目录被 Git 忽略。`scripts/import-cases.mjs` 仅用于作者从原案世界书提取 JSON，永不执行其中 EJS；正式发布运行的是整理后的结构化案件数据。
